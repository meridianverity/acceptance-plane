## Zenodo DOI discipline

Zenodo registers DOIs for uploads when they are published. For manual uploads, Zenodo allows a DOI to be reserved before publication so it can be inserted into files before upload/publication.

Reference: https://help.zenodo.org/docs/deposit/describe-records/reserve-doi/

Zenodo support documentation states that GitHub integration DOIs cannot be pre-reserved before a GitHub release. If a pre-reserved DOI is needed, use a manual Zenodo upload.

Reference: https://support.zenodo.org/help/en-gb/24-github-integration/73-can-i-pre-reserved-a-doi-before-a-github-release

## GitHub immutable releases

GitHub describes immutable releases as releases where assets and the associated Git tag cannot be changed after publication. This supports release integrity and provenance.

Reference: https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases

## CITATION.cff and .zenodo.json

Zenodo documentation states that if both `.zenodo.json` and `CITATION.cff` are present, Zenodo uses `.zenodo.json` metadata for GitHub release archiving while GitHub still uses `CITATION.cff` to display citation suggestions.

Reference: https://help.zenodo.org/docs/github/describe-software/citation-file/
